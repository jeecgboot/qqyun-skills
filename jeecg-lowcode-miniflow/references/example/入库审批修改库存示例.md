# 简流设计器入库审批修改库存示例（主子流程+审批+数据修改）

### 通用复用手法（换租户 / 换表重建本场景，2026-09-03 一次跑通）

1. 第二部分的 4 段完整 JSON 是可直接复用的生产模板：`json.loads` 取出后**递归替换**——旧节点 id（`task`/`Activity`/`Gateway`/`flow`/`group` 前缀）、`formTableId`/`formTableList`、表码（**先替换长串** `form_task{oldId}_oldCode`、再替换可能互为前缀的表码如 `wh_inbound` 与 `wh_inbound_detail`）、字段 model、审批人 username、`customProcessId` 与 `calledElement`（= `process` + 子流程 DB id）
2. 子流程建完按 gotchas **#47** 发布：三层 subEvent 就位后 designer saveFlow 补 `customProcessId=<DBid>` → PUT deployProcess → `/act/process/list` 验 key=`process<DBid>`（旧 manual 两段式已作废）；主流程 deploy 后核验按记录的 **processKey** 查定义，不是 `process<DBid>`（gotchas #43）
3. 跨流程引用变量统一指向父流程 get_more 节点（`formNodeType:"search"` + `formNodeId=父 get_more id`）；`subFormTableObject` 三处一致（父 subprocess 节点 = 子流程 start attr = formTableList[0]），均带 `isSubStart:true`

## 一、精简示例（AI 速读版）

**业务全景**：入库单（wh_inbound）新增 → 入库管理员审批 → 同意后逐条取出入库明细，调用「批量修改库存」子流程（增加库存）→ 回写状态；另一条「取消入库」流程由按钮触发 → 审批 → 调「减少库存」子流程。共 4 个流程（2 主 2 子）。

### 4. 生产数据提炼的关键知识点

1. **主子流程两步创建**：① save_flow 创建 startType="subEvent" 的子流程并发布；② 父流程加 subprocess 节点引用。customProcessId 必须是子流程的**纯数字雪花 DB ID**（如 970715167916728320），传 processKey 后缀会静默创建空白子流程——register_subprocess_id(processKey, dbId) 可自动注入（仅脚本侧给父流程注入 DB id，与引擎定义注册无关）。⚠️ **"发布成功但定义查无 process+DBid"的真根因是子流程记录缺 customProcessId 字段**（deploy 注册出的 key 拼错，不是假发布）——按 `gotchas.md` **#47** 配方：designer saveFlow 补 customProcessId=<DBid> → PUT deployProcess → `GET /act/process/list?pageNo=&pageSize=50` 验 key=process+DBid version≥1（旧 manual 两段式已作废）。
2. **subFormTableObject 三处一致**：父流程 subprocess 节点 attr.subFormTableObject = 子流程 start 节点 attr.subFormTableObject = formTableList[0]，都带 isSubStart: true，从上游 get_more 的 formTableList 条目复制而来。
3. **跨流程字段引用靠 formNodeType="search" + formNodeId=父流程 get_more 节点 ID**：子流程内 get_one 的 sourceTaskId、data_update 的 val、data_add 的 formModel 引用全部指向父流程 get_more 节点（"task970715006964506624"），而不是子流程自己的 start。
4. **父→子传参 inVariableModels**：默认 4 条（applyUserId/dataId/JG_LOCAL_PROCESS_ID→JG_SUB_MAIN_PROCESS_ID/handleDataId），脚本自动补齐，无需手写。
5. **审批结果分支有两种生产形态**：① suggest 意见分支（btn 前缀 ID、type=8、按钮名=分支名，脚本 opinion 节点）；② approve_result 审批结果分支（Gateway 前缀、分支 resultVal Y/N，上游 approver 必须 hasResultBranch=true + addable=false，脚本暂无 builder 需手动构建）。
6. **updateFields 的 optType 是数据修改核心**：1=覆盖赋值（状态回写）、2=增加（入库累加库存）、3=减少（出库扣减库存）——同一张库存表两种流程仅靠 optType 区分加减。
7. **数据分支机制**：get_one 执行后把结果写入内置变量 flow_has_data（1/0），databranch 两分支 content 固定为 ${flow_has_data==1} / ${flow_has_data==0}，branchType=2；分支 conditionNode type=3、priorityLevel 1/2。
8. **data_update 默认更新触发记录**：build_data_update_node 默认 formTableSourceNodeType="table"；更新 get_one 查询结果必须通过 attr 覆盖为 "search"（本示例库存更新即如此，写错会更新错误记录）。
9. **subFlowList（主流程根节点）**：记录引用的子流程（subProcessId=子流程 DB id + subNodeName），生产数据首条可能为 null 占位；主流程根节点 startType 与 attr.startType 一致（tableEvent/buttonEvent），子流程根节点恒为 "manual" + attr.subEvent。
