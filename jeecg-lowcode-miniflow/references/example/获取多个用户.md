## 一、精简示例（AI 速读版）

获取多个系统人员/部门/角色（get_more_sysinfo，实际类型 data_get_udr_more）与"获取单个用户"节点同构，共 6 种取数方式，差异在节点 type 与 delegate。

### 1. 从工作表用户/部门/角色字段获取多条（selectType 1-3）

```python
# ① 用户字段：取工作表用户组件字段对应的多个用户
{
    "type": "get_more_sysinfo",                   # 实际生成 type=data_get_udr_more
    "name": "从用户字段获取多条",
    "getType": "user_field",                      # → selectType=1（查 sys_user）
    "sourceTaskId": "start",
    "fieldIds": ["select_user_1776156412644_695177"],  # 工作表中的用户组件字段 model
    "noDataType": 1,
},

# ② 部门字段：getType="dept_field"（selectType=2），fieldIds 填部门组件字段
{
    "type": "get_more_sysinfo",
    "name": "从部门字段获取多条",
    "getType": "dept_field",
    "sourceTaskId": "start",
    "fieldIds": ["select_depart_1776156404894_859529"],
    "noDataType": 1,
},

# ③ 角色字段：getType="role_field"（selectType=3），fieldIds 填角色组件字段
{
    "type": "get_more_sysinfo",
    "name": "从角色字段获取多条",
    "getType": "role_field",
    "sourceTaskId": "start",
    "fieldIds": ["org_role_1776156424044_622887"],
    "noDataType": 1,
},
```

### 2. 从组织架构查询多条（selectType 4-6）

```python
# ④ 组织人员：按姓名模糊查询
{
    "type": "get_more_sysinfo",
    "name": "从组织人员中获取多条",
    "getType": "org_user",                        # → selectType=4（查 sys_user）
    "conditions": [
        {"rule": "like", "ruleName": "全模糊", "valueType": "1",
         "val": "张",
         "field": "realname",                     # 系统表字段：姓名
         "columnName": "姓名", "type": "text", "valType": "text",
         "dbType": "string"},
    ],
    "noDataType": 1,
},

# ⑤ 组织部门：正确写法按 departName 过滤
{
    "type": "get_more_sysinfo",
    "name": "从组织部门中获取多条",
    "getType": "org_dept",                        # → selectType=5（查 sys_depart）
    "conditions": [
        {"rule": "like", "ruleName": "全模糊", "valueType": "1",
         "val": "<部门名称关键词>",
         "field": "departName",                   # ⚠️ 部门表条件字段应为 departName
         "columnName": "部门名称", "type": "text", "valType": "text",
         "dbType": "string"},
    ],
    "noDataType": 1,
},

# ⑥ 组织角色：正确写法按 roleName 过滤
{
    "type": "get_more_sysinfo",
    "name": "从组织角色中获取多条",
    "getType": "org_role",                        # → selectType=6（查 sys_role）
    "conditions": [
        {"rule": "like", "ruleName": "全模糊", "valueType": "1",
         "val": "<角色名称关键词>",
         "field": "roleName",                     # ⚠️ 角色表条件字段应为 roleName
         "columnName": "角色名称", "type": "text", "valType": "text",
         "dbType": "string"},
    ],
    "noDataType": 1,
},
```

### 3. getType 枚举速查

| getType | selectType | 数据来源 | 查询的系统表 |
|---|---|---|---|
| `user_field` | 1 | 工作表用户组件字段（fieldIds） | sys_user |
| `dept_field` | 2 | 工作表部门组件字段（fieldIds） | sys_depart |
| `role_field` | 3 | 工作表角色组件字段（fieldIds） | sys_role |
| `org_user` | 4 | 组织架构查询（conditions） | sys_user |
| `org_dept` | 5 | 组织架构查询（conditions） | sys_depart |
| `org_role` | 6 | 组织架构查询（conditions） | sys_role |

### 4. 生产数据提炼的关键知识点

1. **与 get_one_sysinfo 的差异只有两处**：节点 type 为 `data_get_udr_more`、delegate 为 `${getUserDeptRoleMoreDelegate}`；其余参数（getType/selectType/fieldIds/conditions/dbType/tenantId）完全同构。**content / tenantId 的落库规则（顶层 content=卡片来源行 `工作表 "来源名"`、attr.tenantId=当前登录租户）同样适用**——见《获取单个用户示例.md》「5. ⚠️ content / tenantId 落库修正」（2026-09-09 用户 UI 实测纠正）。
2. **组织架构查询（4-6）的 formTableList 条目 formTableId 为 `form_{节点ID}_`**（formTableCode 为空串），由脚本自动生成，无需手写。
3. **生产数据踩坑（复制粘贴遗留）**：附录 JSON 中"从组织部门/角色中获取多条"的搜索条件误用了 `realname`（姓名）+ val "张"；对照《获取单个用户示例.md》可知部门/角色节点正确字段应为 `departName`/`roleName`——照抄生产数据时需按字段语义修正（上方精简示例已给正确写法）。
4. **字段获取（1-3）不写 conditions**，用 fieldIds；userFormTableField/deptFormTableField/roleFormTableField 之外的列表字段传 `[]`。
5. **noDataType 默认 1**（继续执行），配合数据判断分支时改 2。
6. **典型用途**：取到的多条人员数据配合 subprocess 节点批量逐条发起子流程（见《主子流程配置示例.md》）。
