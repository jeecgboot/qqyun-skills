## 一、精简示例（AI 速读版）

主子流程 = **父流程**（get_more 取关联多条 + subprocess 节点）+ **独立创建的子流程**（subEvent 触发）。**先建子流程、再建父流程**，父流程的 subprocess 节点引用子流程的数据库 ID。

### 1. 父流程：从单条记录获取关联记录（get_more，selectType=3）

```python

    "processName": "主子流程配置",

    "lowAppId": "<低代码应用ID>",

    "titleField": "input_1775650756203_925880",

    "nodes": [
        {
            "type": "get_more",
            "id": "task968466439507976192",      # ⚠️ 自定义 ID，subprocess 节点要引用
            "name": "从单条记录获取关联记录",
            "selectType": 3,                     # 3=从单条记录的关联字段取多条
            "formTableCode": "cai_gou_shen_qing_swdd",

            "sourceTaskId": "start",             # 关联源记录来自触发节点
```

### 3. 子流程本身：subEvent 触发 + 审批节点

### 4. 两步创建：先子流程、后父流程

```python
from miniflow_creator import build_process_json, save_flow, deploy_flow, register_subprocess_id

# ① 创建并发布子流程
sub_pj = build_process_json(sub_config)
result = save_flow(api_base, token, sub_config, sub_pj)
sub_db_id = result['result']['id']                     # 子流程数据库 ID
register_subprocess_id(sub_config['processKey'], sub_db_id)  # 登记：父流程自动注入 processId
deploy_flow(api_base, token, sub_db_id)

# ② 创建父流程（subprocess 节点的 customProcessId 填子流程 DB ID）
config["nodes"][1]["customProcessId"] = sub_db_id
main_pj = build_process_json(config)
save_flow(api_base, token, config, main_pj)
```

> ⚠️ **发布与验证（2026-09-03 定论）：** 子流程（subEvent）deploy 后必须用 `GET /act/process/list?pageNo=&pageSize=50` 验证 key=`process<DB_ID>` 定义存在，否则主流程 callActivity 运行时报 `Process definition process<DB_ID> was not found`。**"发布成功但查无定义"的真根因 = 记录缺 `customProcessId` 字段（deploy 注册出的 key 拼错），API 配方见 `gotchas.md` #47（designer saveFlow 补 customProcessId → PUT → 校验），旧版 manual 两段式与"必须 UI 发布"已作废。** 子流程 JSON 另需三层 startType 全 subEvent（gotchas #31）。`register_subprocess_id` 仅负责父流程节点自动注入 DB id，与引擎定义注册无关。

### 5. 生产数据提炼的关键知识点

1. **subprocess 节点 ID 用 `Activity` 前缀**（如 `Activity968466391625801728`）；`calledElement`/`processId`/`customProcessId` 三处都指向子流程：`calledElement="process{DB_ID}"`、`processId=DB_ID`、`customProcessId=DB_ID`。生产数据中 `processId` 曾为空串（导致点开子流程空白），脚本强制要求 customProcessId 为纯数字雪花 ID（≥15 位）并自动注入 processId。
2. **subFormTableObject = 复制 + 加 isSubStart**：内容取自上游 get_more 节点的 formTableList 条目，额外加 `isSubStart: true`；父流程 formTableList 中该 get_more 条目同样带 `isSubStart: true`。
3. **子流程触发方式是 subEvent**：保存在 `attr.startType`，root 的 `startType` 仍为 "manual"；子流程 attr 里 `formTableCode`/`formTableName` 指向子表（采购明细）而非主表，`startEventType` 为 "add|update"。
4. **子流程带 `subFlowSourceInfo` 回链**：记录 mainProcessId/mainProcessName/nodeName（由前端回填）；父流程根节点带 `subFlowList`（subProcessId + subNodeName），API 创建时无需手工填写。
5. **父→子默认传递 4 个变量**（inVariableModels，脚本自动生成）：applyUserId、dataId、JG_LOCAL_PROCESS_ID→JG_SUB_MAIN_PROCESS_ID、handleDataId。
6. **子流程 formTableList 首条即 subFormTableObject**（nodeType 显示 "search"、nodeTypeMain 为 "getMore"），后续照常追加"流程参数"条目。
