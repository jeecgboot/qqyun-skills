## 一、精简示例（AI 速读版）

会签节点 = 审批节点（`type: "approver"`）配置多个审批人 + 指定 `approvalMode`。脚本按 approvalMode 自动补全 `completionCondition`（完成条件）：

| approvalMode | 名称 | completionCondition（脚本自动） | isSequential |
|---|---|---|---|
| 3 | 所有审批人通过 | `${nrOfCompletedInstances/nrOfInstances==1}` | false（并行会签） |
| 4 | 通过只需一人 | `${nrOfCompletedInstances/nrOfInstances>0}` | **true（串行，脚本默认）** |
| 5 | 半数通过 | `${nrOfCompletedInstances/nrOfInstances>=0.5}` | false |
| 6 | 按比例投票 | `${nrOfCompletedInstances/nrOfInstances>=ratio}`（ratio 动态生成） | false |
| 7 | 自定义 | 无（必须自己传 `attr.completionCondition`） | false |

五种会签方式的 config 精简写法：

```python
# ① 所有审批人通过（并行会签）
{
    "type": "approver",
    "name": "会签(所有审批人通过)",
    "approvalMode": 3,
    "approverGroups": [{
        "approverType": "candidateUsers",           # 多用户
        "approverIds": ["qinfeng", "admin"],        # 用户账号
        "approverNames": ["秦风", "admin"],          # 显示名（与 IDs 一一对应）
    }],
},

# ② 通过只需一人（脚本默认串行 isSequential=true）
{
    "type": "approver",
    "name": "会签(通过只需一人)",
    "approvalMode": 4,
    "approverGroups": [{
        "approverType": "candidateDepts",           # 按部门
        "deptIds": ["c6d7cb4deeac411cb3384b1b31278596"],   # 部门数据库 ID
        "deptNames": ["北京国炬软件信息"],
    }],
},

# ③ 半数通过
{
    "type": "approver",
    "name": "会签(半数通过)",
    "approvalMode": 5,
    "approverGroups": [{
        "approverType": "candidateGroups",          # 按角色
        "roleIds": ["admin"],                       # ⚠️ 填角色 Code，不是数据库 ID
        "roleNames": ["管理员"],
    }],
},

# ④ 按比例投票（ratio 60%，必须放在 attr 里）
{
    "type": "approver",
    "name": "会签(按比例投票)",
    "approvalMode": 6,
    "attr": {"ratio": 0.6},                         # ⚠️ 投票比例在 attr.ratio，脚本据此生成完成条件
    "approverGroups": [{
        "approverType": "candidatePosts",           # 按职务
        "postIds": ["1958470912214368258"],         # 职务数据库 ID
        "postNames": ["部长"],
    }],
},

# ⑤ 自定义（completionCondition 必须自己传）
{
    "type": "approver",
    "name": "会签(自定义)",
    "approvalMode": 7,
    "attr": {
        "completionCondition": "${nrOfCompletedInstances/nrOfInstances>0.2}",  # ⚠️ 自定义必须手写，否则为 null
    },
    "approverGroups": [{
        "approverType": "candidateUsers",
        "approverIds": ["admin", "jeecg"],
        "approverNames": ["admin", "JEECG演示"],
    }],
},
```

审批人组类型与填充字段对照：

| approverType | 含义 | 填的字段 |
|---|---|---|
| `candidateUsers` | 多个用户 | `approverIds` + `approverNames` |
| `candidateDepts` | 部门 | `deptIds` + `deptNames`（数据库 ID） |
| `candidateGroups` | 角色 | `roleIds` + `roleNames`（**角色 Code**） |
| `candidatePosts` | 职务 | `postIds` + `postNames`（数据库 ID） |

### 生产数据提炼的关键知识点

1. **approvalMode 与 completionCondition 自动映射**：3/4/5 用固定公式、6 按 `attr.ratio` 动态生成（`${nrOfCompletedInstances/nrOfInstances>=0.6}`）、7 必须手写 `attr.completionCondition`，否则为 null（自定义模式下审批流程不会按条件完成）。
2. **approvalMode=4（一人通过）默认串行**：脚本自动设 `isSequential=true`，其余模式并行——与生产数据一致（一人通过节点 `isSequential: true`，其余 `false`）。节点 content 因此显示"串行会签"/"并行会签"。
3. **会签审批人组可混合类型**：本生产数据 5 个会签节点依次用了 candidateUsers（用户）、candidateDepts（部门）、candidateGroups（角色）、candidatePosts（职务）、candidateUsers，说明会签只关心人数与完成条件，人员来源随意。
4. **candidateGroups 的 roleIds 必须填角色 Code**（如 `"admin"`）：脚本会校验，检测到纯数字长 ID 直接报错（实战踩坑：误填角色数据库 ID 导致审批人解析为空）。
5. IDs 与 Names 必须成对填写（approverIds/approverNames、deptIds/deptNames、roleIds/roleNames、postIds/postNames），缺 Names 会导致节点 content 为空、前端选人框空白。
6. 审批人组 ID 格式 `group{时间戳}`、节点 attr（approvalMethod/sameMode/collection 等 22 个默认字段）均由脚本自动生成，无需手写。
