# 简流设计器分支节点示例

> **文档结构说明（双结构）：**
> - **一、精简示例（AI 速读版）** — 使用 `miniflow_creator.py` 的 config 简化格式，带中文注释，AI 直接照抄即可运行
> - **二、完整 JSON 附录（来自生产数据）** — 真实 processJson 全量结构，供排障、精确复刻、人工核对

## 一、精简示例（AI 速读版）

分支类型一览（脚本 type → 真实 processJson type）：`exclusive`→`exclusive`、`parallel`→`parallel`、`inclusive`→`inclusive`、`opinion`→`suggest`、`data_branch`→`databranch`；`approve_result` 无 builder，需手动构建（见第 6 节）。

### 1. 排他分支（exclusive）— 互斥路由

满足条件只走第一个命中的分支，必须有一个默认分支（isDefault=True）。

```python
{
    "type": "exclusive",                 # 排他网关：只走第一个满足条件的分支
    "name": "路由",
    "conditionNodes": [
        {
            "name": "成交客户",
            "priorityLevel": 1,          # 优先级，数字越小越先判断
            "branchType": 1,             # 1=条件分支 2=默认分支
            "conditions": [              # 简化写法：单组条件，组内多条件默认 AND
                {
                    "rule": "eq",        # eq/ne/lt/le/gt/ge/like/notLike/in/not_in/between/null/notNull（分支下 not_in=不是任何一个，勿写 notIn）
                    "ruleName": "等于",
                    "field": "select_1775649166520_177631",    # 触发表单字段 model
                    "columnName": "客户状态",                    # 字段名（条件展示文本用）
                    "val": "成交客户",    # 固定值；in 规则为数组
                    "type": "select",    # 字段类型：text/number/money/select/date/user/dept 等
                    "valueType": "1",    # 1=固定值
                    "valType": "select", # 值类型（省略时脚本取 type）
                }
            ],
            "nodes": [                   # 该分支下的子节点链（脚本自动串联）
                {"type": "approver", "name": "总经理审批",
                 "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                                     "approverIds": ["admin"], "approverNames": ["admin"]}]},
            ],
        },
        {
            "name": "潜在客户",
            "priorityLevel": 2,
            "conditions": [
                {"rule": "eq", "ruleName": "等于",
                 "field": "select_1775649166520_177631", "columnName": "客户状态",
                 "val": "潜在客户", "type": "select", "valueType": "1", "valType": "select"}
            ],
            "nodes": [
                {"type": "approver", "name": "部门经理审批",
                 "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                                     "approverIds": ["admin"], "approverNames": ["admin"]}]},
            ],
        },
        {
            "name": "其他情况",            # ⚠️ 必须有且只有一个默认分支
            "isDefault": True,           # 默认分支不写 conditions/conditionGroup
            "priorityLevel": 3,
            "nodes": [
                {"type": "approver", "name": "上级审批",
                 "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                                     "approverIds": ["jeecg"], "approverNames": ["JEECG演示"]}]},
            ],
        },
    ],
}
```

**多组条件（conditionGroup 完整写法）**：组内多条件默认 AND，多组之间为 OR（生产数据中两组 matchType 分别为 `"AND"`/`"and"`，前端展示「…且… 或 …且…」）：

```python
{
    "name": "大客户",
    "priorityLevel": 3,
    "conditionGroup": [                  # 与 conditions 二选一，脚本优先读取 conditionGroup
        {
            "matchType": "AND",          # 组内关系：空/AND=且，and=或
            "queryItems": [
                {"rule": "eq", "ruleName": "等于", "field": "select_1775648798126_168238",
                 "columnName": "客户类型", "val": "企业客户", "type": "select",
                 "valueType": "1", "valType": "select"},
                {"rule": "ge", "ruleName": "大于等于", "field": "money_1775629278035_887563",
                 "columnName": "注册金额", "val": 1000000, "type": "money",
                 "valueType": "1", "valType": "money"},
            ]
        },
        {
            "matchType": "and",          # 与上一组的关系：and=或（组间 OR）
            "queryItems": [
                {"rule": "eq", "ruleName": "等于", "field": "select_1775648798126_168238",
                 "columnName": "客户类型", "val": "个人客户", "type": "select",
                 "valueType": "1", "valType": "select"},
                {"rule": "gt", "ruleName": "大于", "field": "money_1775629278035_887563",
                 "columnName": "注册金额", "val": 100000, "type": "money",
                 "valueType": "1", "valType": "money"},
            ]
        },
    ],
    "nodes": [
        {"type": "approver", "name": "审批人",
         "approverGroups": [{"approverType": "candidateDepts", "assigneeType": "assigneeByName",
                             "deptIds": ["c6d7cb4deeac411cb3384b1b31278596"],
                             "deptNames": ["北京国炬软件信息"]}]},
    ],
}
```

脚本自动生成的字段（无需手写）：分支 `id`/`pid`/`type=3`/`content`（`[字段名 规则 值]` 展示文本）；条件分支 attr 中的 `branchForm`+`formTableCode`（从 form_config 注入）；conditionGroup 内每组的 `id`。

### 2. 并行分支（parallel）

所有分支同时执行，全部完成后才继续。分支无条件判断。

```python
{
    "type": "parallel",                  # 并行分支：所有分支同时执行
    "name": "并行",
    "conditionNodes": [                  # 分支只有名字 + 子节点，无条件
        {
            "name": "并行1",
            "nodes": [
                {"type": "approver", "name": "总经理",
                 "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                                     "approverIds": ["jeecg"], "approverNames": ["JEECG演示"]}]},
            ],
        },
        {
            "name": "并行2",
            "nodes": [
                {"type": "approver", "name": "董事长",
                 "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                                     "approverIds": ["jeecg"], "approverNames": ["JEECG演示"]}]},
            ],
        },
    ],
}
```

脚本自动生成：聚合节点 `childNode={"type": "polymerize", "id": 网关ID+"1"}`（后续节点自动接在聚合节点之后）；`conditionNodes[].type=10`（不是 3）、`branchType=2`、`conditionGroup=[]`、`content="任意(其他)"`。

### 3. 包含分支（inclusive）

所有满足条件的分支都执行（可走多个分支），与 exclusive 的写法同构，区别只在"互斥 vs 多路"。

```python
{
    "type": "inclusive",                 # 包含分支：满足条件的分支都走
    "name": "相容",
    "conditionNodes": [
        {
            "name": "分支1",
            "priorityLevel": 1,
            "conditions": [
                {"rule": "in", "ruleName": "是其中一个",
                 "field": "select_1775649166520_177631", "columnName": "客户状态",
                 "val": ["成交客户", "非成交客户"],   # ⚠️ in 规则的 val 必须是数组
                 "type": "select", "valueType": "1", "valType": ""}
            ],
            "nodes": [
                {"type": "approver", "name": "经理审批",
                 "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                                     "approverIds": ["admin"], "approverNames": ["admin"]}]},
            ],
        },
        {
            "name": "分支2",
            "priorityLevel": 2,
            "conditions": [
                {"rule": "eq", "ruleName": "等于",
                 "field": "select_1775648798126_168238", "columnName": "客户类型",
                 "val": "企业客户", "type": "select", "valueType": "1", "valType": "select"}
            ],
            "nodes": [
                {"type": "approver", "name": "董事长审批",
                 "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                                     "approverIds": ["jeecg"], "approverNames": ["JEECG演示"]}]},
            ],
        },
    ],
}
```

脚本自动生成：聚合节点 `type="inclusive_end"`（不是 polymerize）、ID=网关ID+"1"；每个条件分支 attr 必须携带 `branchForm`+`formTableCode`（脚本自动注入）。

### 4. 意见分支（opinion / suggest）

审批人处理任务时手动选择按钮，分支名=审批界面按钮名。必须紧跟审批节点。

```python
{
    "type": "opinion",                   # 也接受 "suggest"；真实 processJson type 为 "suggest"
    "name": "多分支",
    "conditionNodes": [
        {
            "name": "同意",              # ⚠️ 分支名 = 审批界面按钮名
            "nodes": [
                {"type": "approver", "name": "总监审批",
                 "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                                     "approverIds": ["jeecg"], "approverNames": ["JEECG演示"]}]},
            ],
        },
        {
            "name": "不同意",            # 无子节点的分支省略 nodes，不会生成 childNode 键
        },
    ],
}
```

脚本自动生成：gateway ID 前缀 `suggest_`、分支 ID 前缀 `btn`（不是 flow）、分支 `type=8`（不是 3）、分支 attr 仅 `{"priorityLevel": 2}`。

### 5. 数据判断分支（data_branch / databranch）

基于 get_one 查询结果自动分流：有数据/无数据。**必须紧跟 `emptyAction=3` 的 get_one 节点**（脚本强校验，不满足直接报错；枚举：1=继续执行/2=新增记录后继续/3=中止或进分支）。

```python
# ⚠️ 数据分支的前置节点：get_one 必须紧邻其前，且 emptyAction=3
{
    "type": "get_one",
    "name": "获取单条数据",
    "formTableCode": "cai_gou_shen_qing_swdd",
    "formTableName": "采购申请",
    "emptyAction": 3,                    # ⚠️ 必须为 3：无数据时中止并进入数据判断分支
    "conditions": [],                    # 查询条件见「获取单条数据」示例
},
{
    "type": "data_branch",               # 脚本类型名；真实 type 为 databranch（脚本自动转换）
    "name": "数据判断",
    "conditionNodes": [
        {
            "name": "有数据",            # content 自动生成 ${flow_has_data==1}
            "nodes": [
                {"type": "data_update", "name": "更新记录",
                 "formTableCode": "cai_gou_shen_qing_swdd", "formTableName": "采购申请",
                 "formTableSourceTaskId": "task968451160803549184",   # ⚠️ get_one 节点 ID
                 "attr": {"formTableSourceNodeType": "search"},       # ⚠️ 覆盖默认 table：更新查询到的记录
                 "updateFields": [
                     {"field": "date_1775650764724_977189",
                      "val": {"formNodeType": "system", "variableValue": "nowTime",
                              "variableName": "当前时间"},
                      "fieldType": "date", "type": "date", "valType": "variable"}
                 ]},
            ],
        },
        {
            "name": "无数据",            # content 自动生成 ${flow_has_data==0}
            "nodes": [
                {"type": "notice", "name": "系统消息",
                 "attr": {"noticeType": "system", "noticeContent": "没有数据"},
                 "toUserIds": ["user.admin"], "toUserNames": ["admin"]},
            ],
        },
    ],
}
```

底层机制：get_one 执行后把结果写入内置变量 `flow_has_data`（1=有数据，0=无数据）。脚本自动生成：两分支 `content` 固定为 `${flow_has_data==1}`/`${flow_has_data==0}`、`branchType=2`、`priorityLevel=1/2`。

### 6. 审批结果分支（approve_result）— 手动构建

根据上游审批节点的结果（通过/否决）自动分流。**脚本暂无 builder，需手动构建节点**（其余分支类型均有 builder）。

```python
import time

# ① 上游审批节点：脚本照常构建，attr 加 hasResultBranch=True
{
    "type": "approver",
    "name": "经理审批",
    "approvalMode": 1,
    "approverGroups": [{"approverType": "candidateUser", "assigneeType": "assigneeByName",
                        "approverIds": ["admin"], "approverNames": ["admin"]}],
    "attr": {"hasResultBranch": True},   # ⚠️ 启用审批结果分支必须置 True
    # ⚠️ 脚本保存后，还需人工把该节点的 addable 改为 false（禁止其后插入节点），
    #    并把下面的 approve_result 节点挂到它的 childNode（见 ③）
},
```

### 7. 生产数据提炼的关键知识点

1. **六种分支的 type 对照**：脚本 config `exclusive/parallel/inclusive/opinion/data_branch` 分别生成真实 `exclusive/parallel/inclusive/suggest/databranch`；手写 processJson 时 `databranch` 写带下划线（`data_branch`）会导致部署失败；`approve_result` 无 builder 必须手动构建。
2. **approve_result 三处必改**：① 上游 approver `attr.hasResultBranch=true` 且 `addable=false`；② approve_result 节点 `pid` 必填上游审批节点 id（缺失报 `getPid() null`）；③ 每个分支 `pid` 必填 gateway id（缺失报 `getId() null`）；分支 attr 带 `approveResultBranch=true` + `resultVal`（"Y"通过/"N"否决）+ `branchType=2`，下游节点放分支的 `childNode`（不是 `nodes[]`）。
3. **opinion 的 suggest_/btn 前缀**：gateway ID 用 `suggest_{ts}` 前缀、分支 ID 用 `btn{ts}` 前缀（其他分支用 `flow{ts}`）、分支 type=8（其他分支 3 或 10）；分支名=审批界面按钮名；无子节点的分支不生成 `childNode` 键；必须紧跟审批节点。
4. **exclusive 默认分支铁律**：必须有且只有一个 `isDefault=true` 分支（真实 `branchType=2`、`conditionGroup=[]`、content="其他情况进入此流程"）；条件分支 `branchType=1`，attr 必须携带 `branchForm`（formTableCode/formNodeId=start/formNodeType=table）+ `formTableCode`；`queryItems[].name` 固定 null（标签在 `columnName`）；`priorityLevel` 数字越小越先判断。
5. **parallel 聚合节点**：`conditionNodes[].type=10`、`branchType=2/3`、无条件、`content="任意(其他)"`；网关 `childNode` 固定为 polymerize 聚合节点（ID=网关ID+"1"），并行分支汇合后的后续节点自动接在聚合节点之后。
6. **inclusive 与 exclusive 的差异**：满足条件的分支都执行；聚合节点 `type="inclusive_end"`（不是 polymerize）；`in` 规则 `val` 必须是数组（如 `["成交客户", "非成交客户"]`）。
7. **data_branch 前置强校验**：必须紧跟 get_one 且 `emptyAction=3`，脚本在 build_node_chain 中校验，不满足直接抛错；两分支 content 固定 `${flow_has_data==1}`/`${flow_has_data==0}`、`branchType=2`、`priorityLevel=1/2`；get_one 把结果写入内置变量 `flow_has_data`。
8. **分支内子节点用 `nodes` 数组**（脚本链式串联并自动计算 level/pid）；approve_result 例外：子节点直接放在 conditionNode 的 `childNode` 字段。
9. **level 为字符串**：网关与分支 attr 的 level 都是字符串（"1"/"2"），分支内子节点 level 自动 +1；生产数据中 approve_result 网关 level 为 "2"。
