## 一、精简示例（AI 速读版）

审批节点 = `type: "approver"`。核心是 `approverGroups` 数组：`approverType`（选人方式）+ `assigneeType`（分配方式）决定填哪些字段。

| approverType | assigneeType | 填的字段 | 取值说明 |
|---|---|---|---|
| `candidateUser` / `candidateUsers` | `assigneeByName` | `approverIds`+`approverNames` | 指定用户（账号） |
| `candidateDepts` | `assigneeByName` | `deptIds`+`deptNames` | 部门（数据库 ID） |
| `candidateGroups` | `assigneeByName` | `roleIds`+`roleNames` | 角色（**角色 Code**） |
| `candidatePosts` | `assigneeByName` | `postIds`+`postNames` | 职务（数据库 ID） |
| `candidateUser(s)` | `assigneeByExp` | `expressionsIds`+`expressionsNames` | 公式表达式 |
| `candidateUsers` | `assigneeByVariable` | `variableTitle`+`variableContent`+`formTableType` | 表单字段取值 |

```python
                     "approverNames": ["admin", "JEECG演示"]}]},   # 显示名，成对必填

# ② 选择部门
{"type": "approver", "name": "选择部门",

                     "deptIds": ["c6d7cb4deeac411cb3384b1b31278596", "6d35e179cd814e3299bd588ea7daed3f"],
```

### 2. 指定公式（assigneeByExp）


### 6. 生产数据提炼的关键知识点

1. **roleIds/roleNames 必须同时填**；且 candidateGroups（按角色）时 roleIds 填**角色 Code**（如 `"admin"`），不是数据库 ID——脚本检测到纯数字长 ID 会直接报错（实战踩坑：误填角色数据库 ID 导致审批人解析为空、流程卡死）。
2. **所有 IDs/Names 字段成对出现**：approverIds/approverNames、deptIds/deptNames、postIds/postNames、expressionsIds/expressionsNames——缺 Names 会导致节点 content 为空、前端选人框空白。
3. **assigneeByVariable 三件套缺一不可**：`variableTitle`（显示名）+ `variableContent`（字段定位对象：formTableCode/formTableId/nodeId/nodeType/fieldName/fieldType/fieldLabel）+ `formTableType`。`nodeId`+`nodeType` 决定取数来源：`start`+`table`=触发表单字段，get_one 节点 ID+`search`=查询结果字段（**写错 nodeType 会取到错误的表**）。
4. **部门字段审批必须 `isNeedTranslateToUserIds: true`**：把部门翻译成用户列表；缺该标记审批人可能为空。
   > ⚠️ **2026-09-16 实测补强（用户报障「部门下人员没收到任务」）**：这里的「审批人可能为空」不是"设计器面板看着空"，而是**运行时任务谁都收不到**——save/deploy 全绿、记录新增照常起实例、`/act/task/list` 里任务也在，只有 `/act/task/myTodo` 能看出没人收到。同轮还踩到第二处：`assigneeByName`（指定成员）的 `approverIds` 必须写**裸账号**（`["admin"]`），写成 `user.admin` 同样静默无任务（`user.` 前缀是**消息节点** `toUserIds` 的写法）。四种形态对照与正反例验收法见 gotchas #90。
   > 另：**办理人=表单字段时 `approverType` 用复数 `candidateUsers`**（指定成员/发起人用单数 `candidateUser`）——线上在跑的「表单字段办理人」组**全部**是复数，单数无生产样本。
5. **发起人审批的坑**：`${applyUserId}` 节点生产数据中 `assigneeIsEmpty=1`、`skipApproval=1`（发起人审批自动跳过，避免自己审自己卡流程）。
6. **审批节点表单绑定自动注入**：attr 中 formTableCode/formTableId/formTableSourceTaskId（"start"）/formTableSourceNodeType（"table"）由脚本从 form_config 注入，是字段权限生效的必要条件，无需手写。
7. **sameMode 是系统内部字段**（用户=1/部门=2/角色=1/职务=4，前端按组类型自动改写），脚本统一填 1，无需手写。
