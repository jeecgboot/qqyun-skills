## 一、精简示例（AI 速读版）

运算节点对应脚本 `type: "operation"`（真实 type=`function`），用 `funType` 区分算法：

| funType | 说明 | config 关键字段 |
|---|---|---|
| `number` | 数值四则运算 | `formula`（字段ID格式：类型_时间戳_随机数） |
| `date` | 日期加减时间 | `funText`（如 `+10Y`）+ `attr.dateFieldVal` + `attr.dateFunctionFormat` |
| `date-diff` | 日期时长计算 | `attr.dateFieldVal` + `attr.dateFieldEndVal` + `attr.dateFunctionFormat` |
| `record` | 统计 get_more 条数 | `sourceTaskId`（get_more 节点ID）+ `formTableCode` + `formTableName` |
| `fun` | 函数计算（CONCAT/IF 等） | `formula`（与 number 同写法） |

> ⚠️ **fieldNames 必传（2026-09-08 实测）：** number/fun 节点 config 必须带
> `fieldNames: {字段model: 中文名}`（用 `fetch_form_fields` 结果反转：`{m['model']: cn for cn, m in fo.items()}`）。
> builder 据此写 funContext 条目 `fieldText` 中文、生成中文 content；**不传则 fieldText 为空 → 设计器公式框/节点卡片显示字段 key 而非中文名**。
> 条目 hash 前端规则 = `md5(规范 8 键条目 JSON 的 UTF-8 原文, 紧凑序列化)`（键序 field/formTableCode/formNodeId/formNodeType/variableValue/formNodeName/tableText/fieldText，无 variableName）；
> `md5(字段ID)` 或 `ensure_ascii=True` 转义风格算出的 key 前端展示公式时重算匹配不上 → 编辑器回退显示 `{{hash.字段}}` 占位符原文。

> ⚠️ **funType 显式（2026-09-08 修正）：** number 省略时默认 `number`；**fun 类型（CONCAT/IF 等）早期 builder 按默认 number 落库**，引擎会按四则解析 CONCAT 出错。builder 现已支持自动识别（formula 以函数名 `XXX(` 开头 → fun），但 config **显式写 `'funType': 'fun'` 最稳**；date / date-diff / record 必须显式 funType。

### 1. 数值运算（funType: number）——formula 自动解析（推荐）

```python
{
    "type": "operation",
    "name": "数值运算",
    "funType": "number",                        # 默认即 number，可省略（显式更稳）
    "formula": "money_1775629278035_887563*12",   # 字段ID格式：类型_时间戳_随机数，脚本自动提取并生成 funContext
    "sourceTaskId": "start",                      # 字段所在数据源节点（start=触发记录字段）
    "fieldNames": {"money_1775629278035_887563": "注册金额"},  # {字段model: 中文名}，必传（缺则字段显示 key）
}
```

脚本自动生成：`funText: "{{hash.money_1775629278035_887563}}*12"`、`funContext: {hash: URL编码的字段引用JSON}`、`operationMode: "cache"`、`decimals: 2`。

### 2. 日期加减时间（funType: date）

```python
{
    "type": "operation",
    "name": "为日期加减时间",
    "funType": "date",
    "funText": "+10Y",                       # 日期偏移表达式（Y=年/M=月/d=天等）
    "attr": {
        "dateFieldVal": {                    # 被加减的日期字段引用
            "variableValue": "date_1776162654792_637160",
            "formTableCode": "ke_hu_shen_qing_co38",
            "variableName": "注册时间",
            "formNodeType": "table",
            "formNodeId": "start",
            "formNodeName": "工作表事件触发",
        },
        "dateFunctionFormat": {              # 计算格式定义（date 与 date-diff 必填）
            "argument": "date",              # 入参类型
            "result": "date",                # 结果类型
            "end": "2",                      # 精度
            "out": "d",                      # 输出单位
        },
    },
}
```

### 3. 日期时长（funType: date-diff）——两个日期的差

```python

    "type": "operation",
    "name": "时长",
    "funType": "date-diff",
    "attr": {
        "dateFieldVal": {                    # 开始日期（字段引用，同 date 示例）
            "variableValue": "date_1776162654792_637160",
            "formTableCode": "ke_hu_shen_qing_co38",
            "variableName": "注册时间",
            "formNodeType": "table",
            "formNodeId": "start",
            "formNodeName": "工作表事件触发",
        },
        "dateFieldEndVal": {                 # 结束日期（可引用系统变量）
            "formNodeType": "system",
            "variableValue": "nowDate",      # 当前日期
            "variableName": "当前日期",

        "dateFunctionFormat": {              # 必填，含义同 date
            "argument": "datetime",
            "result": "datetime",
            "end": "2",
            "out": "d",
        },
    },
}
```

### 4. 统计条数（funType: record）——统计 get_more 节点的数据条数

```python
# 前置：获取多条数据（get_more），id 由脚本生成后记录，供 record 引用
{
    "type": "get_more",
    "name": "获取多条数据",
    "getType": 1,                            # 1=从工作表直接查询多条
    "formTableCode": "cai_gou_shen_qing_swdd",
    "formTableName": "采购申请",
    "conditions": [                          # 查询条件（可省略）
        {
            "rule": "lt",                    # 小于
            "ruleName": "小于",
            "valueType": 3,                  # 3=val 是变量对象
            "val": {                         # ⚠️ val 可以是系统变量/字段引用对象
                "formNodeType": "system",
                "variableValue": "nowDate",
                "variableName": "当前日期",
            },
            "field": "date_1775650764724_977189",
            "columnName": "采购申请日期",
            "type": "date",
            "valType": "variable",           # valType 与 valueType 配套：variable=变量
        }
    ],
    "emptyAction": 1,                        # noDataType：1=无数据继续执行
    "getDataType": 1,                        # 1=缓存（record 统计时引用）
},
{
    "type": "operation",
    "funType": "record",
    "name": "统计数据条数",
    "sourceTaskId": "task968459802755899392",  # ⚠️ 上游 get_more 节点 ID
    "formTableCode": "cai_gou_shen_qing_swdd",
    "formTableName": "采购申请",
    "getDataType": 1,                        # 与 get_more 的 getDataType 一致
}
```

脚本自动构建 funContext（nodeId/formTableCode/getDataType/formTableId/formTableName）和 funText，且 record 类型默认 `operationMode: "everyTime"`（实时统计）。

### 5. 函数计算（funType: fun）——CONCAT/IF 等

```python
{
    "type": "operation",
    "name": "函数计算",
    "funType": "fun",                        # ⚠️ 显式必填（历史 bug：省略会按默认 number 落库；builder 现可自动识别，仍以显式最稳）
    # formula 自动解析对 fun 类型同样适用（字段ID格式：类型_时间戳_随机数）
    "formula": "CONCAT(input_1775629274119_420857,'是',IF(money_1775629278035_887563>=10000,'重要客户','一般客户'))",
    "sourceTaskId": "start",
    "fieldNames": {"input_1775629274119_420857": "客户名称",
                   "money_1775629278035_887563": "注册金额"},   # {字段model: 中文名}，必传
}
```

### 6. 生产数据提炼的关键知识点

1. **funType 五枚举**：`number`（四则）、`date`（日期加减）、`date-diff`（日期时长）、`record`（统计 get_more 条数）、`fun`（CONCAT/IF 等函数）。
2. **number/fun 用 formula 最简**：脚本按 `类型_时间戳_随机数` 正则自动提取字段 ID 并生成 funContext（key=md5(字段ID)、value=URL编码的字段引用 JSON），funText 自动替换为 `{{hash.字段ID}}` 占位符。生产数据中 funContext 的 key 是 md5(完整字段引用 JSON)，两者机制一致，均由脚本生成无需手写。
3. **date/date-diff 必须显式传 `attr.dateFieldVal`（+`dateFieldEndVal`）和 `attr.dateFunctionFormat`**（argument/result/end/out 四键），funText 如 `"+10Y"`；dateFieldEndVal 可引用系统变量 `nowDate`。
4. **record 统计条数三要素**：`sourceTaskId` 指向上游 get_more 节点 ID、`formTableCode`/`formTableName` 与 get_more 一致、`getDataType` 同 get_more 节点；operationMode 固定 `everyTime`，其余类型默认 `cache`。
5. **下游引用运算结果**：data_add/data_update 等节点取结果用 `formNodeType: "function"` + `variableValue: "result"`，formTableCode 写 `function-{funType}`（如 `function-number`）。⚠️ 走 **data_update.updateFields** 引用时，条目**顶层**还须带 `valueType: 3` + `valType: "variable"`（date 字段另带 `options.format`），漏键 save/deploy 全绿但设计器把值当固定值显示；function 节点的 formTableList 登记须按链序插 start 表条目后（gotchas #58，2026-09-09 实测）。
6. **get_more 查询条件的 val 支持对象**（系统变量/字段引用），此时 `valueType=3` 且 `valType="variable"`；固定值则 valueType="1"。
7. 每个 function 节点都会在 start.formTableList 登记一条（`form_{节点ID}_function-{funType}`，含 operationMode/decimals），脚本自动收集，无需手写。
8. **fieldNames 必传（2026-09-08 实测）**：number/fun 节点 config 带 `fieldNames: {字段model: 中文名}`（`fetch_form_fields` 结果反转），builder 据此写 funContext `fieldText` 中文并生成中文 content；缺它字段显示 key。funContext 条目 hash 前端规则 = md5(规范 8 键条目 JSON 的 UTF-8 原文, 紧凑序列化)——`md5(字段ID)` 或 `ensure_ascii=True` 转义风格算出的 key 前端不认，编辑器回退显示 `{{hash.字段}}` 原文。
9. **builder 生成的 content（画布卡片渲染键）date/date-diff/record 三种残缺（2026-09-08 实测）**：date 只写 `+30D`（丢字段名前缀）、date-diff 留空、record 写 `form_<节点id>_<表code>` 裸存储串——与 UI 原生卡片（date=`注册时间  +10Y`、date-diff=`当前日期 减 注册时间`、record=`统计数据条数：采购申请`）不符。**新建/保存前按 UI 原生格式自愈这三个 content**（date=`'<字段中文名>  <funText>'`；date-diff=`'<结束字段名> 减 <开始字段名>'`；record=`'<节点name>：<表中文名>'`），number/fun 的 content 已含中文公式、get_more 已正常，勿动。content 只影响卡片展示，不影响公式编辑/引擎执行——**与"公式区显示 {{hash}}/编码串"的 funText 主因（gotchas #54）是独立的两处差异，别混**。
10. **funText 占位符与 funContext key 一致性（2026-09-08 实证 + 踩坑）**：占位符必须是 `{{<32hex md5>.<字段model>}}`，md5 = 解码后 value 的规范 8 键紧凑 JSON（键序 field/formTableCode/formNodeId/formNodeType/variableValue/formNodeName/tableText/fieldText，ensure_ascii=False）——同字段同上下文的条目 hash 与 builder 产物逐字节一致（规则经实测确认）。funContext 值只转义 `"` `{` `}` 与非 ASCII（`,` `:` 原样，python 用 `quote(s, safe=':,.-_/?')`）；解码等价、不影响 key，对齐可减前端疑点。⚠️ **重写 funText 时禁止用 funContext 的 value 替换占位符 key**——value 是 URL 编码串恒 ≠ key，会把公式改成一整段 `{{%7B%22field…%7D…}}` 乱码（2026-09-08 实测损坏过、已还原）。详见 gotchas.md #54。（builder 已内置该编码 + fun 自动识别，**新建流程不再需要手工处理**；存量脏流程按 #54 修）
