## 一、精简示例（AI 速读版）

本示例是一条「供应商」表 update 触发的表达式审批链：审批人不是固定用户，而是按表达式动态查找（部门负责人 / 岗位上级 / 表单部门字段负责人），生产数据为 9 级审批链。

### 1. 表达式审批人清单（生产数据实测）

| 表达式 | 查找目标 |
|---|---|
| `${flowNodeExpression.getApplyDepartLeaders(execution)}` | 发起人所属部门的负责人 |
| `${flowNodeExpression.getDepartLeaders(applyUserId)}` | 发起人所属所有部门的负责人 |
| `${flowNodeExpression.getLevel1DepartLeaders(applyUserId)}` | 上一级部门负责人 |
| `${flowNodeExpression.getLevel2DepartLeaders(applyUserId)}` | 上二级部门负责人 |
| `${flowNodeExpression.getLevel3DepartLeaders(applyUserId)}` | 上三级部门负责人 |
| `${oaFlowExpression.getUserSuperPositionLevel1(applyUserId)}` | 上一级岗位人员 |
| `${oaFlowExpression.getUserSuperPositionLevel2(applyUserId)}` | 上二级岗位人员 |
| `${oaFlowExpression.getUserSuperPositionLevel3(applyUserId)}` | 上三级岗位人员 |
| `${flowNodeExpression.getFormDepartLeaders(execution,'<部门字段model>')}` | 表单某部门字段的负责人 |

### 2. 审批节点 config（表达式审批人）

```python
{
    "type": "approver",
    "name": "发起人部门负责人",
    "approvalMode": 1,                        # 1=任一审批人通过即可
    "approverGroups": [
        {
            "approverType": "candidateUsers",   # ⚠️ 表达式审批人必须用 candidateUsers（复数）
            "assigneeType": "assigneeByExp",    # 按表达式查找
            "levelMode": 1,
            "expressionsIds": [
                "${flowNodeExpression.getApplyDepartLeaders(execution)}"
            ],
            "expressionsNames": ["获取发起部门负责人"],   # 节点显示名（content）
        }
    ],
}
```

多个表达式审批人串联：nodes 列表依次放多个 approver 即可。表单部门字段负责人的写法：

```python
{
    "type": "approver",
    "name": "审批人",
    "approverGroups": [
        {
            "approverType": "candidateUsers",
            "assigneeType": "assigneeByExp",
            "expressionsIds": [
                "${flowNodeExpression.getFormDepartLeaders(execution,'select_depart_1776392104337_127005')}"
                #                                                       ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                #                                                       表单中部门字段的 model
            ],
            "expressionsNames": ["获取表单部门字段的负责人"],
        }
    ],
}
```

对比：固定用户审批人用 `candidateUser` + `assigneeByName` + `approverIds`/`approverNames`（见审批节点示例）。

### 3. 生产数据提炼的关键知识点

1. **表达式审批人三件套**：`approverType: "candidateUsers"` + `assigneeType: "assigneeByExp"` + `expressionsIds`（表达式字符串数组）。用 candidateUser（单数）的 approverIds 写法时表达式不生效，前端会按空审批人处理。
2. **两个表达式命名空间**：`flowNodeExpression.*`（部门负责人系列 + 表单部门字段负责人）与 `oaFlowExpression.*`（岗位级别系列）。部门负责人支持 Level1~3 逐级；岗位支持 getUserSuperPositionLevel1~3。
3. **参数约定**：getApplyDepartLeaders / getFormDepartLeaders 用 `execution` 参数（后者第二参数为表单部门字段 model），其余全部用 `applyUserId` 参数。
4. **每个 approver 节点都带完整 DEFAULT_APPROVER_ATTR**（approvalMethod / sameMode / ratio / collection / elementVariable 等 20+ 字段），脚本 build_approver_node 自动补齐，config 无需手写。
5. **节点 content 字段 = expressionsNames**（审批链显示文本），脚本从 approverGroups 自动提取。
