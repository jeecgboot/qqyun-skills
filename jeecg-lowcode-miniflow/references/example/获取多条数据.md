## 一、精简示例（AI 速读版）

获取多条记录（get_more，实际类型 data_get_more）的 3 种取数方式（selectType 1/3/4），组合批量新增（data_add）与审批节点的完整链路。

### 1. 从工作表获取多条（get_more，selectType=1，按记录id 过滤）

```python
{
    "type": "get_more",
    "id": "task966309911246053376",               # ⚠️ 自定义 ID，data_add 批量新增要引用
    "name": "从工作表获取多条",
    "selectType": 1,                              # 1=从工作表直接查询多条
    "formTableCode": "sub_table_design_1775650992740_930671",
    "formTableName": "采购明细",
    "conditions": [
        {"rule": "eq", "ruleName": "等于", "valueType": 2,
         "val": {"variableValue": "_id",          # ⚠️ 引用触发记录的"记录id"系统字段
                 "formTableCode": "cai_gou_shen_qing_swdd",
                 "variableName": "记录id",
                 "formNodeType": "table", "formNodeId": "start",
                 "formNodeName": "工作表事件触发"},
         "name": None, "field": "_id",            # ⚠️ 目标表条件字段=记录id
         "columnName": "记录id",
         "type": "input", "valType": "variable"}
    ],
    "sortType": "desc",
    "getDataType": 1,                             # 1=缓存
    "emptyAction": 1,
}
```

### 2. 从单条记录获取关联记录（get_more，selectType=3）

```python
{
    "type": "get_more",
    "name": "从单条记录获取关联记录",
    "selectType": 3,                              # 3=从单条记录的关联字段取多条
    "formTableCode": "cai_gou_shen_qing_swdd",
    "formTableName": "采购申请",
    "sourceTaskId": "start",                      # 关联源记录来自触发节点
    "relationField": "link_record_1775648472154_528874",  # link-record 关联字段 model
    "attr": {
        "linkFormTableCode": "sub_table_design_1775648472154_528874",
        "linkFormTableName": "订单明细",
        "linkFormTableType": 1,
    },
    "getDataType": 2,                             # 2=实时查询（每次引用都查库）
    "emptyAction": 1,
}
```

### 3. 基于多条数据逐条新增（data_add，addDataType=2）

### 5. 从新增节点获取记录（get_more，selectType=4）

```python
{
    "type": "get_more",
    "name": "从新增节点获取记录",
    "selectType": 4,                              # 4=从上游 data_add 节点取刚新增的记录
    "formTableCode": "sub_table_design_1775648472154_528874",
    "formTableName": "订单明细",
    "sourceTaskId": "task966310224627671040",     # ⚠️ 上游 data_add 节点 ID
    "getDataType": 1,
    "emptyAction": 1,
}
# formTableSourceNodeType 自动设为 "plus"，无需手写
```

### 6. 生产数据提炼的关键知识点

1. **get_more 的 selectType 枚举 1/3/4**：1=工作表查询、3=关联字段取多条（`sourceTaskId`+`relationField`）、4=从 data_add 节点取新增记录（`sourceTaskId` 指向上游 data_add，formTableSourceNodeType 自动为 "plus"）。
2. **"记录id 等于"条件**：field 用 `_id`、valueType=2、val 是变量引用对象（variableValue `_id` 取触发记录的记录id）。link-record 控件选记录后再查目标表的写法见《获取单条数据.md》第 5 节。
3. **getDataType 控制取数时机**：1=缓存（执行到节点时取一次）、2=实时（每次引用都查库）；selectType=3 关联子表场景生产数据用 2（实时），批量新增引用场景用 1。
4. **approvalMode 双字段陷阱**：生产数据中 attr.approvalMode=2 与节点顶层 approvalMode=5 并存，**实际生效的是节点顶层的 5**（半数通过，completionCondition `${nrOfCompletedInstances/nrOfInstances>=0.5}`）；脚本只写节点顶层 approvalMode，attr 里的旧值可忽略。
5. **data_add 批量新增必须补全 4 个 source 字段**：formTableSourceTaskId（get_more 节点 ID）/ formTableSourceNodeType（"getMore"）/ formTableSourceCode（源表 code）/ formTableSourceId（`form_{get_more节点ID}_{源表code}`），外加 formTableSourceGetDataType=1。
6. **节点链路顺序**：get_more(1) → get_more(3) → data_add(2) → approver → get_more(4)；get_more(4) 挂在 approver 的 childNode 下，即"审批之后从新增节点取记录"可以接在审批节点之后。
