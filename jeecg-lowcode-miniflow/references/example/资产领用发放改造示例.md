# 简流设计器资产领用发放改造示例（主子流程+按明细改台账，2026-09-07 全链路跑通）

> **场景：** 主流程「资产领用流程」（资产领用申请单 `zc_receive` 新增触发）在「部门负责人审批」之后插入：
> 获取多条记录（取关联明细）+ 并行子流程。新建 subEvent 子流程「资产领用发放子流程」，数据对象=领用资产明细行，
> 逐条：查主单 → 按明细.关联固定资产查台账 → 数据分支（有数据 → 更新台账：状态=在用、保管人=主单.领用人；
> 无数据 → 跳过该行直接结束）。
>
> **同款结构直接复用：** 资产归还/调拨/报废/维修（都是 主表+明细+固定资产台账 三表）改造时，只改「①–⑤常量」后
> 整个脚本一次跑完（探查 1 次 py + 本脚本 1 次 py，≤2 次）。**字段 model 每次用 `fetch_form_fields` 按中文名现取，禁止照抄**（表单重建后 model 会变）。
>
> ⚠️（2026-09-07 实测教训，见 gotchas #51）：`fetch_form_fields` 返回 `{中文名: {model,...}}`，**取 model 一律 `v['model']`**——把中文名误填进 data_update 的 `field` 会导致该条更新被引擎静默跳过（同节点其他字段正常写入，症状=部分字段没更新且无报错）。改子流程后发布**必须** designer saveFlow 补存（带 customProcessId + 最新 updateCount）+ PUT deploy，且 `/act/process/list` 查 version 递增才生效（#47 配方同样适用于修改）。
>
> ⚠️（2026-09-07 二次实测）：主表→明细 link 也用 options.sourceCode 匹配、可能是 `sub_table_design_…`；若为反查 link 自加辅助函数，**返回值约定 `(中文名, model)`，一律 `_, m = hits[0]` 解构**——方向写反会把中文名存进 linkFormTableField，save 不报错但运行时取不到明细。自查法：打印/回读看到 link 值形态不是 `sub_table_design_` / `link_record_` 前缀即异常。

> ⚠️（2026-09-07 资产调拨驳回教训，见 gotchas #53）：模板内 data_get_one（查主单/查台账）全是 selectType=1「工作表查单条 `_id=link值`」写法。**需求点名「从关联字段获取单条」时该写法不满足、会被驳回**——须把对应节点外科重写为 attr.selectType=3：源=明细行上游 get_more（formTableCode/Name/Id=明细表、formTableSourceTaskId=get_more id）、`linkFormTableField`=明细上 link model、`linkFormTableCode/Name`=目标表、content=`关联表 "目标表名"`、formTableList 该节点条目 selectType=3。只改 ①–⑤ 常量 ≠ 满足点名的取数方式。

## 通用复用手法（换流程 / 换表 / 换字段）

1. **探查一次打全**：`query_flow(API, TOKEN, process_name=…)` 拿主流程记录（id/processKey/lowAppId/tenantId/updateCount 与节点树，确认锚点审批节点名与其下游）；`fetch_app_forms(API, TOKEN, 租户)` 定位应用工作表 code；`fetch_form_fields(API, TOKEN, 表code, 租户)` 按中文名取字段 model（link-record 返回 `{sourceCode,titleField}`）。
2. 本脚本已按 #47 配方发布子流程并做引擎定义校验、主流程保存+发布+回读校验，**全部在一个 py 运行内完成**，不再单独开回读轮。
3. 常见坑速查（本模板已内置规避）：三层 subEvent（记录层/processJson 顶层/attr 层）；#47 发布需**创建后回查 updateCount** 再补 `customProcessId` 表单保存；子流程引用父行字段 = `formNodeType:"search"` + `formNodeId=<主流程 get_more 节点 id>`（不是子流程 start）；"判断有没有"一律用目标表 `_id` eq 源 link-record 值；data 分支两分支 content 固定 EL `${flow_has_data==1/0}`。

## 节点 JSON 结构要点（手工拼，勿用 builder 平移）

| 节点 | 结构要点 |
|---|---|
| 主流程 get_more (selectType=3) | attr：`formTableCode/Id/Name`=源主表、`linkFormTableCode/Name/Type`=明细表、`linkFormTableField`=主表 link model、`formTableSourceTaskId:'start'`、`formTableSourceNodeType:'table'`；渲染键五件套；`formTableList` 追加同款条目含 `isSubStart:true` |
| callActivity | attr 内：`calledElement='process'+子流程DBid`、`customProcessId/processId`=DBid、`subFormTableObject`（getMore 形态）、`isMulti:true isSequential:false`、`formTableSourceTaskId`=上游 get_more id；顶层 `listenerData`=MiniCallActivityListener + `inVariableModels` 4 条系统变量；content=`执行流程:XX` |
| 子流程 start 根 | 三层 subEvent（记录层 config / processJson 顶层 / attr 层）；`start.attr.subFormTableObject` = search 形态（`nodeType:'search'` + `nodeTypeMain:'getMore'`），子 `formTableList[0]` 同形；start 渲染键 `content:'发起流程'`；executeListeners/taskListenerData/eventListeners 用本脚本常量 |
| 引用父行字段 | val/条件 = `{formNodeType:'search', formNodeId:<主流程 get_more id>, formTableCode:明细表, variableValue:明细字段model, variableName:…}`（勿指向子流程 start） |
| get_one 查"是否有" | 条件 `field:'_id'` eq link 值；`attr.noDataType=3`（中止流程，或继续执行查找结果分支）；紧跟 databranch |
| databranch | type `databranch`；分支行 content 固定 EL `${flow_has_data==1}`/`${flow_has_data==0}`；分支行 type=3、attr `branchType:2`；下游节点挂分支行 childNode、pid=分支行 id |
| data_update | `formTableSourceTaskId`=上游 get_one id、`formTableSourceNodeType:'search'`、`formTableSourceGetDataType:1`、`formTableId=form_{get_one id}_{表code}`；select 固定值写文案（optType:'1'）；引用另一 get_one 字段 val=`{formNodeType:'search', formNodeId:<该 get_one id>,…}` + `valueType:2/valType:'variable'` |

## 发布配方（新建 subEvent 子流程，2026-09-07 实测，gotchas #47）

1. `save_flow` 创建子流程（config.startType='subEvent'、processJson 顶层/attr 同为 subEvent）
2. `query_flow(flow_id=…)` **回查最新 updateCount**（创建后是 1，不是 0！传错报「不是最新版本」500）
3. POST `/act/designer/miniDesFlow/api/saveFlow`（form 表单）补 `customProcessId=<DBid>` + `processKey=process<DBid>` + `updateCount=<回查值>`
4. PUT `/act/process/extActProcess/deployProcess {"id":<DBid>}` → 校验 `/act/process/list` 出现 key=`process<DBid>`（接口不可用时 queryById 解 processXml 的 `<process id>`）
5. 主流程：`save_flow(update_count=rec.updateCount)` → `deploy_flow`（主流程 def key = 记录 processKey，与子流程不同）
