# 规格精确命名 + 建库四个坑（2026-09-16 实测）

> **这份不是生成流程的必经关卡**，是「规格怎么写才不返工」的参考。
> 生成走 `build_app.py` + `patch_fields.py` 即可。

---

## ⑨ 规格必须自带精确命名表（2026-09-16 实测）

**前提认知，先记住：需求文档通常就是一段业务描述，没有可对照的现成应用。**
所以规格里的「字段名 / 关联名 / 带出名 / 子表列名 / 标题」**必须在文档里写死**，
不能指望执行者去别处比对、更不能靠业务直觉推。

历轮翻车**全部**出在这里：把 `选择设备` 写成 `设备`、`责任部门名称` 写成 `部门名`、
`含税金额/元` 写成 `含税金额`、子表列名靠猜。**每一个名字都是一次返工。**

**命名表怎么来：用户直接给命名清单时，原样写进规格并声明它是唯一权威**
（业务描述与它冲突时以它为准）；正文里的字段罗列**删掉**——两处都写、两处不一致，
就是返工的源头。

**带出字段名要写「目标表上的真实字段名」，不能写本表显示名。**
带出控件的 `name`（本表显示名）与它引用的源字段名**允许不同**（重名时平台会迫使改名），
规格里声明带出时必须用**后者**。只记本地名 → 目标表上没这个字段 → 预检/补丁全红。

> ⚠️ **但「允许不同」只是平台能力，不是规格能力 —— 规格的 `带出` 只能同名校对，没有重命名入口**
> （2026-09-17 实测，52 表应用为此白跑了 4 轮语法试错）。
> `带出` 是**纯字符串数组**，元素只能是目标表上的真实字段名；落地的控件名 = 源字段名。
> 已试过且全部失败/无效的写法：`"a->b"`、`"a:b"`、`"a=b"`、`{"字段":..,"本地名":..}`、
> `{"name":..,"field":..}`、`["a","b"]` 二元组。
> 想用别的本地名只有两条路：
> 1. **改源表字段名**（把 `客户.联系人名称` 直接命名成 `客户联系人姓名`，下游全部同名带出即可）；
> 2. **建完整单设计补丁**改 `name`（`query_form` → 改控件 `name` → `save_design_from_file`），
>    且注意此时该字段**已存在**会撞名，得先 `delete_widget` 再改名，而 `delete_widget` 会换 `model`、
>    打断引用它的他表 `showField` —— 代价很高，一般不划算。
> **推荐第 1 条**：写规格前就把下游要用的名字定在源表上。

写规格时的判定规则（每条带出都要落在前两档，剩下的逐条标出来）：

| 档 | 判定 | 文档里怎么写 |
|---|---|---|
| A | 目标表上确有同名字段 | 直接写名字 |
| B | 目标表上有这个字段，但名字不同 | `目标表字段名（本地 本地名）` —— **规格写前面的** |
| C | 目标表上找不到 | 标 `⚠`，**在「已知缺陷」节里指定正确字段名**，不能只标不指 |

C 档常见于「复制粘贴建的表」：关联还指着复制前的表，名字也对不上。
**C 档必须在文档里给出替换名**，并顺手核一遍替换名在目标表上真实存在 ——
否则等于把坏绑定换个写法继续传下去。

> `.strip()` 顺手做一遍：名字**首尾**的空白（前导空格、尾部 TAB）在 JSON / 脚本 /
> 预检之间极易被吃掉，留着必然对不上。只去最外层。

## 建库时必踩的四个坑

- **表 code 每轮重新生成**（形如 `t13a7cNN`，NN 恒等于规格里的序号，前缀是当轮
  按「应用名 + appId」算出的哈希）。看板声明若沿用**上一轮**的 code：
  `build_dashboards.py --dry-run` **仍能规划出全部页面**（它不按字面 code 解析），
  所以这不是「必坏」；但**建盘前按表名重映射一次**能把行为钉死
  （表名 →(上一轮 code 表)反查 → 新应用菜单取新 code）。
- **`build_app.py --rows 0` = 不灌测试数据**（交付要求「不需要测试数据」时就用它）。
  灌数段仍会跑一遍并回读，报「无数据 / 异常表 N 张」是**预期结果不是失败**。
- **首页按钮分两批，来源不同**：spec 的 `buttons` 块只声明「打开列表视图」按钮
  （建盘脚本会建）；**「跳转到各张看板」那批要另加** ——
  `qqy_ops.py add-buttons --specs-file <json>`，pageId **必须从新应用的菜单取**
  （`drag` 行的 **`menuUrl`** 列，不是 `id`）。加完回读页面的 `config.chartData`
  数按钮个数。

  > **2026-09-17 起这条已收进 `build_dashboards.py`**：它改成**两趟**——
  > 先把所有盘建完，再统一加按钮。于是 `"page": "<看板名>"` 这种写法在 spec 里
  > 直接可用，不必再手写 pageId、也不必把「首页」排到它要跳转的看板后面。
  > 老版本一趟建成时，「首页」排在前面 → 目标盘的 pageId 还不存在 →
  > `[btn] 找不到看板 xxx`、按钮 `customPage` 为空，**而盘本身照报 `OK:`**（静默半坏）。
  > 跳过已存在的盘时会先查一下盘上有没有按钮组件，没有才补 —— 重跑不会叠加按钮组。
- **标题可以是他表字段 / 关联记录**：构建器解析不了这种标题，会**静默回退**成别的字段
  （实测：某表标题落成了它自己的编号字段，规格要的是上游的 `设备名称`）。
  所以规格里凡是「标题是他表字段/关联记录」的表，**建完必须逐表回读
  `config.titleField` 核对**；不符就手改：
  `design.config.titleField = <该控件 model>` → `save_design_from_file` → 再回读。
